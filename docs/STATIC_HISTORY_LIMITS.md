# 2단계: 공개 자료를 옮길 때의 보호 범위

이 문서는 2단계 구현을 위한 설명입니다. 현재 배포에 보호 기능이 적용됐다는 완료 기록이 아닙니다. 데이터베이스 연결과 새 배포 검증은 대기 중입니다.

## 현재 버전에서 해야 할 일

메모 본문은 저장소와 정적 빌드 결과물에 넣지 않고 학습용 데이터베이스에 보관합니다. 브라우저는 서버 API로 자료를 읽고, 서버 전용 자격은 배포 환경의 비밀 설정에서만 사용합니다. 화면 소스·JSON·JavaScript 번들에 메모 본문이나 서버 전용 키를 넣지 않습니다.

1단계의 data.json을 public/data.json으로 복사하는 빌드 동작도 함께 끝내야 합니다. 최신 Git 트리에서 파일을 지워도 빌드가 다시 생성한다면 정적 노출이 계속됩니다. 새 배포에서 /data.json이 404 또는 메모 0건인지, 화면이 새 서버 API로 계속 동작하는지 각각 확인해야 합니다.

2단계는 공개 정적 파일에서 자료를 분리하는 단계입니다. 로그인 및 사용자별 접근 제어는 3·4단계에서 별도로 구현하고 검증해야 합니다. 데이터베이스에 옮겼다는 사실만으로 비로그인 접근이 막혔다고 주장하지 않습니다. 로그인 보호가 검증되기 전에는 공개 가능한 가상 자료만 사용합니다.

## 이미 공개된 과거 자료의 한계

최신 커밋에서 파일을 삭제해도 이전 Git 커밋에는 내용이 남을 수 있습니다. GitHub의 과거 커밋, fork, clone, 다운로드 사본까지 최신 수정으로 지워지는 것은 아닙니다. 저장소를 나중에 비공개로 바꿔도 이미 받은 사본을 회수할 수 없습니다.

Vercel의 새 배포를 보호해도 과거 배포 URL이나 다른 캐시·저장 사본의 접근 상태는 별도입니다. 최신 배포의 /data.json 검사가 통과했다는 이유로 모든 과거 주소와 외부 사본에서 자료가 사라졌다고 쓰지 않습니다. 기존 배포를 삭제하거나 공개 이력을 다시 쓰는 조치는 별도 확인 없이 실행하지 않습니다.

실제 비밀값이 공개됐다면 소스 삭제만으로 복구되지 않습니다. 해당 자격의 폐기·교체와 노출 범위 확인이 필요합니다. 이번 과제에는 실제 비밀이나 개인정보를 넣지 않고, 제출 설명에도 메모 본문·토큰·개인키를 복사하지 않습니다.

## 배포 후 확인할 증거

- 최신 저장소의 추적 파일과 새 정적 결과물에 메모 본문이 없음.
- 실제 배포 /data.json이 404 또는 메모 0건이며, SPA HTML 응답을 빈 JSON으로 오인하지 않음.
- /aleph.json의 저장소·커밋이 제출 대상과 일치함.
- 첫 화면의 nosniff 또는 CSP 헤더를 실제 응답에서 확인함.
- 자료실 화면이 데이터베이스를 읽는 서버 API로 동작함. 요청 실패는 오류로 표시하고 정상 빈 목록으로 숨기지 않음.
- 위 항목은 배포 후 실제 요청으로 기록함. 아직 실행하지 않은 항목은 미실행으로 둠.
