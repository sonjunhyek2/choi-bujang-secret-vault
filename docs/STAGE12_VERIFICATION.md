# 최종 12단계 점검의 범위

작전실 주소는 /operations.html이며 /api/operations 응답만 화면에 표시합니다. 자체 점검 계획41개와 ALEPH 공식41종 공격은 별개입니다. 자체 목록을 공식 공격 ID와 동일한 것으로 쓰거나, 로컬 연습을 실제 운영 시험으로 바꾸지 않습니다.

`npm run assault:check`는 현재 배포 전후 /aleph.json의 커밋이 같은지 확인하고, 공개 정적 자료·화면·스크립트·원본 공개 키·비로그인·잘못된 토큰 요청6개와 정상 공개 응답2개를 실측합니다. 나머지35개는 계정·승인·운영 엔진을 갖춘 뒤 실행할 대상으로 남습니다. 각 행에는 메서드·경로·기대 결과·실측 HTTP·응답의 요청 번호·확인 시각만 남기며 메모 본문이나 인증 정보는 저장하지 않습니다. 요청 번호가 없으면 미확인이고 미실행의 번호·시각은 null입니다. 보고서는 artifacts/assault-report.json, 화면에서는 「점검 기록 내려받기」로 저장합니다.

작전실에 로그인한 기기가 서버 승인을 받은 경우에만 본인 원본 API 정상 조회를 추가 실측합니다. 본인 사본·복원 수와 마지막 복구 해시는 DB에서 가져오며 다른 계정의 기록을 조회하지 않습니다. 미인증 상태의 작전실 API는 공개 가능한 자기 점검과 규칙만 보여 주고 개인 기록은 반환하지 않습니다. 실제 운영 사건과 신원·세션 회수는 연결하지 않았으므로 「미연결·미확인」입니다. 브라우저 기기 승인 해제와 운영 엔진 신원 회수를 같은 결과로 표시하지 않습니다.

11단계까지 공식100점 판정을 받았지만, 실제 A/B 이메일 계정 브라우저 CRUD·실제 운영 엔진은 별도 미검증입니다. Supabase에서 사본과 복구 감사 이력의 집계가0건인 것을 확인했습니다. 추가 임시 자료 SQL 복원 시험은 도구 확인 만료로 실행되지 않았습니다. 해당 시험을 실제 DB 복구 성공으로 쓰지 않습니다. 로컬 모의 저장소에서는 변조·삭제 복구와 감사 보존, 소유자·해시 거부를 시험했고 DB와 Node의 SHA-256도 동일했습니다.

학생 구현은 판정기·탐지 규칙·설치 화면·자료실·복구·작전실이며, 제공 엔진의 출처는 **ALEPH SDP 엔진 사용**입니다. 실제 mTLS·기기 서명·운영 회수는 제공 엔진과 별도 계약/증거가 필요합니다. 루트 package/ 및 XDR 보너스 양식은 추가 과제용 시작 틀이며, 그 미구현 AI/침해 정보 서버까지 이 자료실이 완성했다고 주장하지 않습니다.
